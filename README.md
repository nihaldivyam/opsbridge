# OpsBridge: Mattermost to Gitea Alert Sync

OpsBridge is a lightweight infrastructure bot written in Go. It connects Mattermost alert threads (generated by Alertmanager/custom bots) directly to Gitea incident tickets. 

Instead of switching context between chat and your issue tracker during an incident, engineers can reply directly to the alert thread in Mattermost to add comments or register time, and OpsBridge will map it to the correct open Gitea ticket.

## ✨ Features

* **WebSocket Listener:** Connects securely to private Mattermost channels using a Bot Token (bypassing Mattermost's webhook restrictions for private channels).
* **Smart Alert Matching:** Parses raw Markdown in Mattermost threads to extract `alertname` and `certname` labels, scanning open Gitea issues to find the exact match without relying on strict, fragile hashes.
* **Gitea Time Tracking:** Natively supports Gitea's time registration via chat. Sending `/spend 15m investigating logs` in Mattermost will log 15 minutes to the ticket and add the comment.
* **Reverse Proxy Support:** Includes dual-layer authentication support, allowing the bot to bypass ingress/Nginx Basic Auth while still authenticating with the Gitea API via token.

## 🏗️ Architecture Workflow

1. A monitoring tool (like `bot_opsmondo` or Alertmanager) posts an alert to Mattermost and creates a ticket in Gitea.
2. An engineer replies to the alert thread in Mattermost.
3. OpsBridge catches the `posted` event via WebSocket.
4. It fetches the parent message of the thread, extracting the `alertname` and `certname`.
5. It fetches an in-memory list of open Gitea issues and matches the strings perfectly (bypassing Gitea's internal search index limits).
6. It pushes the comment or time registration directly to the matched Gitea ticket.

## ⚙️ Configuration & Environment Variables

The bot requires the following environment variables to run. 

### Mattermost Config
| Variable | Description |
|----------|-------------|
| `MATTERMOST_URL` | The base URL of your Mattermost server (e.g., `https://chat.example.com`). Do not include `/api/v4`. |
| `MATTERMOST_BOT_TOKEN` | The Bot Access Token generated in Mattermost Integrations. |

### Gitea Config
| Variable | Description |
|----------|-------------|
| `GITEA_URL` | The base URL of your Gitea server (e.g., `https://gitea.example.com`). |
| `GITEA_TOKEN` | A Personal Access Token with `Write` access to Issues. |
| `GITEA_OWNER` | The Organization or User that owns the repository (e.g., `EnableIT`). |
| `GITEA_REPO` | The name of the repository where incidents are tracked. |

### Proxy Basic Auth (Optional)
If your Gitea instance sits behind a reverse proxy requiring Basic Auth, provide these to satisfy the proxy:
| Variable | Description |
|----------|-------------|
| `GITEA_BASIC_USER` | Basic Auth username. |
| `GITEA_BASIC_PASS` | Basic Auth password. |

## 🚀 Running Locally

1. Clone the repository and initialize the module:
   ```bash
   git clone [https://github.com/nihaldivyam/opsbridge.git](https://github.com/nihaldivyam/opsbridge.git)
   cd opsbridge
   go mod tidy
2. Export your environment variables:
   ```bash
    export GITEA_URL="https://gitea.yourdomain.com"
    export GITEA_TOKEN="your_token"
    export GITEA_OWNER="repoowner"
    export GITEA_REPO="your_repo"
    export MATTERMOST_URL="https://chat.yourdomain.com"
    export MATTERMOST_BOT_TOKEN="your_bot_token"
   ```
3. Run the bot:
   ```sh
   go run cmd/bot/main.go


💬 Usage Examples in Mattermost
Once the bot is in your private alert channel, simply reply to an alert thread.

Adding a Comment:

"I am looking into this CPU throttling issue now."
OpsBridge will post this exact string as a comment on the matched Gitea issue.

Registering Time:

`/ticket 45m cleared the cache and restarted the ArgoCD pods`
OpsBridge will register 45 minutes of time tracking on the Gitea issue and post the accompanying text as a comment explaining the time.
